# 当前结果镜像复现实施规划

## 背景与目标

冻结问题1、2、3当前实际使用的配置、必要中间方案、输入哈希和预期输出哈希，使后续代码能够明确选择镜像配置复现当前结果；不覆盖题目原始附件和现有正式结果。

## 已确认现状

- Q1 `result1_1.xlsx`、`result1_2.xlsx` 已填写，分别有590和574个非零数值单元；无Excel错误值，审计回读误差为0，农业约束可行。
- Q2 `result2.xlsx` 已填写，574个映射单元与 `selected_plan.csv` 逐格一致，最大误差0；农业约束可行。
- Q3历史展示工作簿已迁移为 `doc/results/q3/result3.xlsx`，627个映射单元与 `selected_plan_q3.csv` 逐格一致，最大误差0；这不是题目提供的官方 `result3` 模板。
- Q1/Q2/Q3均未获得全局最优认证，镜像复现的是“当前冻结可行结果”，不是理论最优解。

## 采用方案

每题建立独立目录：

```text
qN_test/configs/current_result_mirror/
├─ config.yaml                    # 当前结果的权威参数
├─ manifest.json                  # 输入、代码、配置、冻结依赖和预期输出SHA-256
├─ README.md                      # 唯一复现命令、状态与限制
└─ frozen_inputs/                 # 仅存储跨阶段且无法由单配置重建的轻量中间方案
```

Q1镜像参数以当前 `audit.csv` 对应的20秒运行版本为准，而不是旧 `repro.json` 中600秒版本；实施时先从日志/代码输出进一步确认其 `delta`、`eta`、seed和命令，发现无法追溯则标记镜像为“结果冻结镜像”，不得声称可从零数值复现。

Q2镜像采用当前 `repro_q2.json` 参数，并绑定Q1基线工作簿哈希。由于求解器超时和并行行为可能导致不同incumbent，验收同时区分：文件级完全一致、指标容差一致、仅约束可行三档。

Q3采用两段式镜像：

1. 冻结全整数发现阶段产生的627条结构方案，存入 `frozen_inputs/q3_discovery_plan.csv`；
2. 精炼配置通过显式路径读取该冻结结构，不再依赖 `outputs/q3/selected_plan_q3.csv`，消除循环输入；
3. 单独提供多种子OOS配置与合格种子列表。

## 工程修改

- 为三个问题新增镜像目录、配置、README和manifest。
- Q3运行器增加 `fixed_pattern_path` 配置；指定后只读该CSV并校验哈希。
- 新增统一只读校验脚本 `scripts/verify_current_result_mirrors.py`：核对输入、冻结中间件和当前结果哈希，并检查四个工作簿非空与CSV回读。
- 可选新增三个一键镜像复现批处理；统一使用 `E:\anaconda\python.exe`。
- 不改动现有默认配置，不覆盖当前结果，不修改原始附件。

## 验收标准

1. 三套镜像配置均能被对应运行器解析。
2. Q3可在清空普通输出目录的副本环境中，从冻结发现结构启动精炼，不依赖旧输出。
3. 校验脚本退出码0，并输出输入哈希、配置哈希、预期结果哈希、Excel非零数和最大回读差。
4. 当前结果工作簿：Q1两份非空且无错误值；Q2为574格、差0；Q3为627格、差0。
5. README明确求解器超时导致的非确定性：随机种子相同不保证MIP超时incumbent字节级相同。

## 风险与回退

- Q1当前 `audit.csv` 与旧 `repro.json` 参数/结果不一致，必须先追溯当前20秒产物来源；追溯失败时只建立结果冻结镜像，不伪造复现命令。
- Q2/Q3包含时间限制MIP，文件级哈希可能无法稳定复现；以约束可行、关键利润与方案距离容差作为第二层验收。
- Q3的K=30缩减Kendall审计失败，镜像必须保留该披露，风险结论继续使用未缩减OOS。
- 任一镜像运行失败时保留现有结果和日志，不自动覆盖主结果。

2. 创建三个镜像目录并冻结配置/必要中间方案。

4. 生成三题manifest及统一校验脚本。
5. 在隔离输出目录执行小规模/固定结构复现测试。
6. 独立P1复验；完整正式重跑由用户单独启动，避免本轮再次运行数小时。

- 不把Q3候选工作簿改称官方 `result3.xlsx`。
- 不覆盖题目附件或当前主结果。
