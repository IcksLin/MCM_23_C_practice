## 3. 模块职责和接口

### 3.1 `algorithms/paths.py`

集中定义绝对解析后的路径：附件、Q2基线、Q3输出、图、日志、报告和候选工作簿。所有路径相对 `q3_test` 推导，禁止依赖启动终端当前目录。

### 3.2 `algorithms/io_data.py`

复用 Q2 的只读 Excel 解析，新增：

```python
load_q2_baseline() -> BaselinePlan
verify_input_hashes(expected: dict[str, str]) -> None
```

读取 CSV 时显式验证列、类型、年份、季次、作物编号和面积非负。Excel 只读输入不得保存。

### 3.3 `algorithms/preprocess.py`

复用 Q2 `ModelData`，新增作物类别映射：

```python
crop_group: dict[int, Literal["grain", "vegetable", "fungi"]]
season_crop_sets: dict[int, set[int]]
```

类别必须来自附件字段或已有清洗结果，不能靠作物名称模糊匹配。

### 3.4 `algorithms/dependency.py`

建议数据类：

```python
@dataclass
class DependencyConfig:
    df: float
    correlation_scale: float
    temporal_rho: float
    loadings: dict[str, dict[str, float]]

@dataclass
class DependencyAudit:
    min_eigenvalue: float
    max_kendall_error: float
    target_kendall: pd.DataFrame
    sample_kendall: pd.DataFrame
    sample_spearman: pd.DataFrame
```

初始状态合同固定为 `g[:, 2024] ~ N(0,1)`，递推仅用于 2025—2030；不得改成零初始化。

核心接口：

```python
build_factor_map(data, cfg) -> FactorMap
build_latent_correlation(factor_map, years) -> np.ndarray
generate_t_rank_scores(n, factor_map, years, seed, df) -> np.ndarray
reorder_lhs_by_ranks(lhs, scores) -> np.ndarray
build_audit_pairs(target_kendall, dimensions, years, threshold=0.10) -> set[tuple[int, int]]
audit_dependency(samples, weights, r_lat, audit_pairs) -> DependencyAudit
```

实现要求：

- 每行载荷平方和小于 1；
- `R_lat` 对称、对角线为 1、最小特征值不低于 `-1e-10`；
- 每个情景只有一个卡方尺度，覆盖全部变量和七年；
- 因子 AR(1)，特异项跨年独立；
- `tau*=2/pi*arcsin(R_lat)`；
- 审计对确定为所有 `|tau*|>=0.10` 的非对角无序对，并强制并入同一维度相邻年份对，不得人工删减；
- 原始样本 Kendall 最大绝对误差不超过 0.05；缩减样本按情景权重算加权 Kendall，方向须一致且最大误差不超过 0.15；
- 不把 `R_lat` 与 Spearman 直接比较。

### 3.5 `algorithms/elasticity.py`

接口：

```python
build_elasticity_matrix(data, scale: float) -> dict[int, np.ndarray]
apply_price_elasticity(base_demand, scenario_price, trend_price, matrices) -> np.ndarray
audit_elasticity(matrices, data) -> ElasticityAudit
```

断言：

- 对角线严格为负；
- 替代边为正，无依据边为 0；
- 不同季次不连边；
- `sum(abs(off_diagonal_row)) <= abs(diagonal)`；
- 输出需求有限且严格非负；
- 当全部价格冲击为 0 时，输出等于基础需求；
- 单个替代品涨价时，目标作物需求方向正确。

### 3.6 `algorithms/scenarios.py`

不要直接重写 Q2 边际逻辑。建议拆成：

```python
generate_q2_marginals(data, n, seed, distribution) -> MarginalScenarioSet
correlate_marginals(marginals, dependency_cfg) -> CorrelatedScenarioSet
apply_market_interactions(scenarios, elasticity_cfg) -> Q3ScenarioSet
```

场景至少保留：

```text
scenario, year, plot, land_type, crop, season,
base_demand, demand, yield, cost, trend_price, price,
macro_factor, climate_factor, demand_group_factor, yield_group_factor
```

保存参数变化率或生成元数据，不要把重复长表作为唯一真源。

### 3.7 `algorithms/scenario_reduction.py`

从 Q2 复制后扩展距离特征：参数变化率、公共因子得分、Q2代理利润。仍使用利润十等频分层、最低10%尾部保护、PAM medoid 和 L1 距离。

新增审计：缩减前后主要 Kendall 方向、误差、最低利润层代表数、权重和、medoid 唯一性。

### 3.8 `algorithms/model.py`

继承 Q2 变量和硬约束。新增：

```python
b[j,t] in {0,1}
w[j,i,t,s] >= 0
```

`b[j,t]` 等于上一年度豆类启用变量的逻辑或；2024 使用 2023 历史状态。加入：

```text
w <= x
w <= A*b
w >= x - A*(1-b)
w >= 0
```

产量系数使用 `q*(x + gamma*w)`。不要写成 `q*x + gamma*w`，否则 `gamma` 的量纲错误。

模型构建接口：

```python
build_q3_model(
    data,
    scenarios,
    beta,
    risk_lambda,
    eta,
    complementarity_gamma,
) -> StochModel
```

### 3.9 `algorithms/solve.py`

启动时动态探测求解器及其能力，至少记录 `supports_mip_start`、`supports_bound` 和 `supports_checkpoint_resume`。当前 SciPy/HiGHS 在 Q2 正式规模中 9 个 lambda 无可行解，因此 Q3 不应直接复制相同运行策略后宣称完成。

求解器优先级：

1. Gurobi/COPT（若环境已有合法许可）；
2. SCIP；
3. HiGHS 原生接口；
4. SciPy `milp` 仅作能力受限回退。

所有后端必须支持检查点、状态与界的记录；只有探测到 `supports_mip_start=True` 时才强制注入 Q2 或上一 `lambda` 解，能力不足时必须在日志和复现清单显式写明，不能伪称已热启动。正式运行若不能得到完整前沿或通过认证，应按退出码 2 结束。具体要求：

- 在后端支持时使用 Q2 方案或上一 `lambda` 方案热启动；
- 每个 lambda 的断点/检查点文件；
- 断电后跳过已有合格 lambda，仅重算失败点；
- incumbent、bound、gap、状态、节点数和时间记录；
- 没有有限 incumbent 时不导出该点工作簿。

三级字典序沿用 Q2。不要把三个目标直接用任意权重相加。

### 3.10 `algorithms/evaluate.py`

接口：

```python
evaluate_fixed_plan(plan, scenarios) -> ScenarioProfitFrame
paired_compare(plan_q3, plan_q2, scenarios, seed) -> ComparisonReport
bootstrap_paired_difference(delta_profit, n_boot, seed) -> BootstrapCI
run_ablation(configs, common_random_stream) -> pd.DataFrame
```

四组消融必须共享边际样本和随机秩流。Q2 组读取冻结方案并只复算，不重新优化；其余三组只开关相关性、弹性/互补组件，保持求解时限、情景数、`beta`、`lambda` 网格和选择规则一致。

### 3.11 `algorithms/risk.py`

集中实现风险指标、前沿资格判定和唯一方案选择。一个点只有在存在有限可行 incumbent 且三级求解均完成时才有资格进入前沿；正式 `frontier_complete=True` 要求 11 个 `lambda` 点全部有资格。唯一选择规则与根目录报告第 12.6 节一致：归一化前沿到端点连线的最大距离至少为 0.02 时选膝点，否则选满足下尾利润达到全前沿最大值 99% 的候选中期望利润最高者；并以固定字段完成字典序破同分。

推荐条件另行计算：Q3 相对 Q2 的平均利润损失不超过 2%，下尾改善为正且成对 bootstrap 95% 区间下界不小于 0；同时输出 1%、3%、5% 门槛敏感性。

## 5. 测试顺序

### 5.1 单元测试

1. `R_lat` 半正定、对角线为1；
2. t分数共享卡方尺度和AR(1)时间结构正确；
3. LHS每维分层不被破坏；
4. Kendall方向及阈值正确；
5. 所有非退化边际范围和递推正确；
6. 弹性符号、稳定条件和零冲击退化正确；
7. `w=x*b` 在 `b=0/1` 两种情况下手算一致；
8. `gamma=0` 严格退化为无互补模型；
9. 固定Q2方案的利润复算与Q2结果口径一致；
10. 共同随机数使两方案利润逐情景一一对应。

### 5.2 P1 最小纵向门禁

建议真实54地块/41作物、2024—2025两年切片、`N0=200,K=5,lambda={0,1}`：

```text
输入哈希
→ 边际LHS
→ t-Copula重排
→ 弹性修正
→ 情景缩减
→ 含w变量MILP
→ 三级求解
→ Q2/Q3共同情景复算
→ 审计
→ 临时OOXML输出
```

作者测试通过后立即派发未参与实现的 P1 质检 Subagent；未通过不得全量求解。

### 5.3 正式计算

推荐顺序：

1. `K=10` 和少量 lambda 验证 warm start/断点；
2. `K=20` 全风险网格；
3. `K=30`；
4. 只有关键指标相差超过2%才上 `K=50`；
5. 5000样本外；
6. 弱中强参数扫描和四组消融；
7. 图表、报告、哈希；
8. P2 独立终检。

## 7. 退出码合同

- `0`：流水线完成，全部硬门槛通过；
- `1`：输入、依赖、模型、审计或导出错误；
- `2`：有可行方案，但风险前沿或最优性认证未达到正式门槛；
- `3`：没有可行方案；
- `130`：用户中断，检查点已安全写入。

断电无法执行清理，因此每个 lambda 完成后必须先原子写检查点，再进入下一点。

## 8. 完成定义

下游 Agent 只有在以下条件全部满足时才能说“实现完成”：

1. P1 独立 PASS；
2. 正式命令真实运行；
3. 全部 lambda 有可追溯状态，前沿选择规则可执行；
4. 农业、相关、弹性、互补、利润和输出审计均通过；
5. Q2/Q3比较使用共同随机数；
6. 9张逻辑图通过图表审计；
7. 复现清单和输出哈希完整；
8. P2 独立 PASS。

否则只能报告当前完成到哪一层，不得用空文件、冒烟结果或未认证解代替正式结果。
